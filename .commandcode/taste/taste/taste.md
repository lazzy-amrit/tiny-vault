# Taste
- Verify target versions / API compatibility before implementing; if the specified version doesn't exist, explain the incompatibility rather than silently targeting another version. Confidence: 0.95
- Strongly prefers minimal, single-purpose implementations: no scope creep (no commands, GUIs, metrics, databases, or unrelated extras), small reliable code, only source + build config + metadata + concise setup instructions. Confidence: 0.9
- Security-conscious: credentials/secrets belong in a private config file and must never be logged. Confidence: 0.85
- Prefers fail-safe data-handling patterns: verify new artifacts (e.g. upload + checksum) before replacing or deleting existing good ones, never delete the only valid copy before its replacement is confirmed, preserve prior state on failure, and update state files atomically. Confidence: 0.85
- Demands thorough runtime verification before delivery, not just successful compilation: after repeated runtime crashes, explicitly asked for proper testing ("test it properly so, i don't get any errors again"); run the software end-to-end (e.g. launch a real server with the built artifact) before claiming done. Confidence: 0.9
- When pasting error stack traces, wants an explicit diagnosis of whether the root cause is code or configuration (and, if code, a fix; if configuration, where and why). Confidence: 0.85
- Prefers essential-only logging (startup, success, failure) and minimal resource/temp-file footprint. Confidence: 0.75
- When he asks "how does X work", answer in a single short, plain-language explanation (he explicitly asked for a "30secs no time waste" explanation of multipart uploads) — no code dumps, no digressions. Confidence: 0.8
- Casually toned, often time-pressed user: when he signals urgency ("under 5 mins", "in a hurry", "i got low on time", "tell me fast don't think much"), give a crisp verdict-first answer immediately and defer optional extras/refactors; execute fast paths (direct API tests) instead of long detours. Confidence: 0.8
- Prefers the agent to run diagnostics itself with credentials he drops in a project `.env` (e.g. test the third-party API directly with boto3/python rather than telling him to run the test), while never printing the secret values. Confidence: 0.8
- When an initial diagnosis points at user-side/web-panel fixes, keep digging for the true root cause (sweep alternate endpoints, regions, configs, run round-trip tests) instead of handing off to "contact support" or assuming user error — he wants the actual cause pinned down with evidence. Confidence: 0.8
- When iterating on an existing project, preserve the current logic and structure and make only the targeted change he asks for ("keep same logic and code just improve") — reuse/drop-in-swap the existing jar and config, don't rewrite or restructure. Confidence: 0.8
- New config options should be self-documenting: an inline comment block directly above the field warning about what the option does, its unit/default ("the number is read as HOURS, default 24"), and any caveat — he asks for this preemptively for important settings. Confidence: 0.75
- When designing commands/controls, split them into permission tiers: at least one status/proof command open to everyone (so any player can see backups are happening) and administrative actions (trigger, history, diagnostics) restricted to operators only. Confidence: 0.75
- Defaults should favor universal compatibility: put provider-specific quirks behind an explicit config toggle (e.g. `mode: "s3"` as universal default, `s5` for FileLu) rather than defaulting to one provider's behavior. Confidence: 0.75
- Cleanup must be automatic, never a manual follow-up step for him: leftovers (temp objects, trash entries, stale mounts from old versions) should be purged by the tool itself on the next run, and deletes should be conditional so absent things create no residue. Confidence: 0.8
- Always respond in English only — he is an English reader and explicitly objected to a reply that contained non-English (Chinese) text. Never mix other languages into explanations or summaries. Confidence: 0.9
